### CI end-to-end path

CI cannot download restricted or bulk real sources, so the Playwright job loads
`philfacilities-ingest load-demo --reset` and supplies the suite's fixture
environment variables with the deterministic synthetic records. The same suite
was re-run locally against a production build backed by that synthetic
database: **47 passed, 5 skipped**. Local runs without the overrides default to
the real records named above; both paths exercise the same assertions.

  → `200`, `total = 9,883`

- `GET /v1/facilities?reference_period_start=2026-10-01&reference_period_end=2026-09-30`
  → `400`, `code = invalid_reference_period`
  with message `reference_period_start must be on or before reference_period_end.`

The filter is inclusive overlap semantics and is also exposed on
`/v1/facilities/within`, `/v1/facilities/nearby`, `/v1/schools`, and
`/v1/health-facilities`. Unknown release period boundaries do not match.

## Search latency (serial loopback, not a load test)

Five requests per query after warm-up:

| Query | Results | Median |
|---|---:|---:|
| `Mulanay` | 40 | 252 ms |
| `Manila` | 832 | 638 ms |
| `Bacolod` | 140 | 1,869 ms |
| `School 01` | 0 | 89 ms |
| `zzzz-no-match` | 0 | 88 ms |

Search now uses an uncorrelated `UNION` of indexed ID branches (name, official
name, source key, address, locality) instead of a correlated `EXISTS`.
Migration `0006_search_trigram_indexes` adds trigram indexes for the text
branches and model indexes cover `official_name`, `address_text`,
`source_record_key`, and `administrative_units.name`. `Bacolod` remains the
slowest measured term; further query-plan and index work is pre-launch
optimization, not a completeness claim.

## Data-integrity controls verified

- Raw source files and immutable releases are preserved outside the public
  surfaces; the working tree excludes `var/` raw files and database dumps.
- Missing values remain null and are not rendered as zero, false, or inactive.
- PSGC leading zeros are preserved; population and geography releases carry
  source URL, agency, reference period, checksum, retrieval time, and parser
  version.
- OSM records remain labelled crowd-sourced, and their bbox-centre coordinates
  remain `map_geocoded` rather than building-level locations.
- No facility is auto-merged; identity candidates remain in the review queue.
- Registry presence is not treated as proof of current operational availability.
- Public queries require a rights-cleared dataset and an approved/published
  release. DepEd EBEIS internal records and blocked official sources do not
  appear in public results.
- Failed new releases are quarantined; a previously published release keeps its
  `published` status so a failed re-ingestion cannot hide working data.
